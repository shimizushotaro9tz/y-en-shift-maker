# シフト自動作成（児童養護施設ユニット向け）

ユニットの勤務表を条件に合わせて自動で作成し、Excel（.xlsx）でダウンロードできる Web アプリです。
すべての処理はブラウザ内で行い、入力した内容は外部のサーバーに送信しません。

**▶ アプリを開く：https://shimizushotaro9tz.github.io/y-en-shift-maker/**

## 使い方

ふだんは**シフト表の画面**だけで作業します。行が日付（1(日)、2(月)…）、列が職員（職員1、職員2…）の表です。

1. 画面上部の ‹ › で、作成する月を選びます。
   表のいちばん上の前月の行（連勤の上限の日数分。初期値は5日）に、前月末の勤務を入れます。まずは「前月のExcelを読み込む」で、前月にダウンロードした Excel から取り込んでください。前月の Excel がない場合は、各マスで勤務を選んで入力することもできます。すべて埋まらないと「シフト生成」は押せません。月を切り替えると、前月の行は未入力に戻ります。
   職員の人数は「職員 6 名 [－] [＋]」で増減できます（追加した職員は 職員F3、F4… で、どちらのホームにも入れる職員になります。6名を超えたときは、休みを9日以上確保できる日にだけ、D を自動で追加します）。途中の職員を外すときは、列見出しの ✕ を押します。
2. 決まっている勤務（会議・研修・有休など）は、マスのプルダウンで選んで固定します（🔒）。「希望休」を選ぶと、できるだけ休みにします。
   明け公（E公。宿直明けの日を公休にする）を入れたい場合は、表の上の「明け公（E公） [－] 0日 [＋]」で日数を指定します。どの日にするかは生成時に選び、その日は代わりに A（休日は C）を1人増やします。
3. 「シフト生成」を押すと、固定していないマスを条件に合わせて埋めます。
4. 生成後にマスを選び直すと、その勤務で固定され、条件を確認し直します。
5. 必ず守る条件をすべて満たしていれば、「Excelダウンロード」で .xlsx をダウンロードできます。

設定を変えるときだけ、右上の「設定」を押します。

| 設定の項目 | 内容 |
| --- | --- |
| 基本設定 | 平日と休日の切り替え（土日祝は自動で休日）、設定ファイルの書き出し・読み込み |
| 職員 | 仮名、担当ホーム（ホームA／ホームB／どちらも）、宿直の可否・回数、公休数、並び順（シフト表の列の順）。前月の最後の7日間の勤務（月をまたぐ宿直明け・連勤・連休の判定に使う。月を切り替えると未入力に戻る） |
| 勤務区分 | 記号、名称、ホームでの役割（早番／断続／遅番）、宿直とのつながり、勤務日・公休・有休に数えるか |
| 必要人数 | 平日・休日の基本の人数、休日の3人勤務の体制、日付ごとの人数（会議の日など）。人数は**ちょうどその人数**にし、どの勤務にも入らない職員は「公」になる |
| ルール | 職員が基本の人数（6名）を超えたときに追加する勤務（D。休みを理想の日数確保できる日だけ）、公休の上限（9日。超えた休みは有休にする）、休み（公休＋有休）の日数の下限、連勤の上限、宿直の回数、翌日に入れない組み合わせ、計算時間 |

設定（職員の仮名・担当ホーム、勤務区分、必要人数、ルール）はブラウザに自動で保存されます。その月の入力（固定・希望休、前月末の勤務、日付ごとの人数、生成結果）は、入力履歴を残さないため保存せず、ページを再読み込みしたり閉じたりすると初期状態に戻ります。別のパソコンで使う場合は、「設定」→「基本設定」から設定ファイル（JSON）を書き出し、読み込んでください。

> 公開される Web アプリです。氏名などの個人情報は入力せず、仮名を使ってください。

## 初期設定

| 項目 | 初期値 |
| --- | --- |
| 勤務区分 | A（断続）、B（日勤）、C（早番）、D（遅番）、BE・DE（宿直入り）、EC・EA（宿直明け）、公、有、公E・有E（宿直入り）、E公・E有（宿直明け） |
| 平日の人数 | EA 1、A 1、D 1、DE 1、ほかは公休 |
| 休日の人数 | EC 1、C 1、D 1、DE 1、ほかは公休 |
| 連勤 | 5連勤まで |
| 宿直の回数 | 自動（月の宿直数 ÷ 宿直できる人数。6名なら5〜6回、7名なら4〜5回）、職員間の差は1回まで |
| 翌日に入れない組み合わせ | D の翌日に C |
| 公休数 | 自動（必要人数から決まる休みの総数を全員で均等に分ける） |

## 条件の扱い

- **必ず守る条件**
  - ホームごとの体制：各ホームに早番か断続が1人、遅番が1人。担当外のホームには入らない（休日の3人勤務の日は、断続の人を早番・遅番の人と別のホームに置く）
  - 休み（公休＋有休）は月8日以上（上限なし）。理想は9日以上で、9日を下回る場合は「できるだけ避けたい点」として表示
  - 公休は1人9日まで（超えた休みは生成時に有休にする）
  - シフト表で固定した勤務
  - 日付ごとの人数
  - 宿直入りの翌日は宿直明け
  - 連勤の上限
  - 宿直の回数の範囲と職員間の差
  - 2日連続の宿直なし（宿直入りの間隔の最低日数。ルールで変更可）
  - 翌日に入れない組み合わせ
  - 宿直できない職員には宿直を入れない
  - 職員ごとに指定した公休数
- **できるだけ満たす希望**
  - 希望休
  - 休日の3人勤務（A または EA・C または EC・DE）は、4人体制では休みを確保できない場合と、3人勤務にすれば希望休をかなえられる場合だけ使う（希望休のほうを優先）
  - DE→EA→DE のように、宿直明けの翌日にまた宿直に入る形を避ける（優先度：高）
  - 2〜3連勤を中心にする（4連勤は許容。1日だけの勤務と5連勤は避ける）
  - 5連休以上を避ける
  - 宿直と次の宿直の間隔をできるだけ空ける（目安：月の日数 ÷ 宿直回数）
  - 公休数・各勤務の回数・休日の休みを均等にする

作成結果は次の3つのどれかとして表示します。

| 表示 | 意味 |
| --- | --- |
| 必ず守る条件をすべて満たしています | 完成 |
| この条件では作れません | 作成前の確認で、人数や回数が明らかに合わないと分かった場合。見直す点を表示します |
| 時間内に見つかりませんでした | 作れる可能性はあります。計算時間を延ばすか、条件をゆるめてください。違反のある参考案を表示しますが、Excel はダウンロードできません |

## Excel の内容

- **勤務表**シート：行が日付、列が職員の縦長の表です（色分けはしません）。右側には、日ごとの勤務別の人数と備考（休日の3人勤務の日・祝日）を表示します。下には、職員ごとの公休・有休・休み計・勤務日数・宿直回数・勤務回数を集計します。集計は数式なので、Excel 上で勤務を直すと再計算されます。
- **勤務区分**シート：記号の一覧です。
- **条件チェック**シート：できるだけ避けたい点の一覧です。

## 前月の Excel の読み込み

「前月のExcelを読み込む」で、前月にこのアプリからダウンロードした .xlsx を読み込むと、表の前月の行が埋まります。本当に前月の勤務表かは、次の点で確かめます。合わない場合は読み込みません。

1. ファイルに記録された年月（ダウンロード時に埋め込む）
2. 表のタイトル（「2026年10月 勤務表」）と、ファイル名の年月
3. 各行の日付と曜日が、前月のカレンダーと一致するか

## GitHub Pages で公開する

ビルドは不要です。このフォルダの内容をそのまま公開します。

1. GitHub で新しいリポジトリを作り、このフォルダの内容を push します。
2. リポジトリの **Settings → Pages** を開きます。
3. **Build and deployment** の **Source** で「Deploy from a branch」を選びます。
4. ブランチに `main`、フォルダに `/ (root)` を選んで保存します。
5. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます。

## 手元で動かす

自動作成を別スレッド（Web Worker）で実行するため、`index.html` をダブルクリックで開くのではなく、簡易サーバーを使ってください。ダブルクリックで開いた場合も動きますが、計算中は画面が止まります。

```sh
python -m http.server 8000
# ブラウザで http://localhost:8000/ を開く
```
